# Website Architecture

## Purpose

Document the public-site information architecture as implemented or planned, separate from privileged product workflows.

**Status:** Current working standard
**Last Updated:** 2026-08-08

## Current public routes

The repository includes public pages for home, how it works, pricing, FAQ, contact, privacy, terms, booking, and appointment-access experiences. Public content should guide discovery and preparation; admin, payments, and provider operations remain server-side.

## Public journey

Home → service understanding → booking → confirmation and communications → token-protected Client Workspace → provider-hosted remote session.

## Information architecture rules

Give each public page one clear primary purpose and H1. Keep public navigation focused on functional, approved routes. Do not surface internal dashboards, diagnostics, or implementation status.

## To Be Finalized

The final public navigation map, approved About-page content, and any localized content require content approval.
