# Communication Standards

## Purpose

Set clear, privacy-conscious communication expectations.

**Status:** Current working standard
**Last Updated:** 2026-08-08

## Current implementation context

The repository contains communications, reminder, and delivery-processing boundaries. Communications should remain concise, customer-safe, and linked only to authorized customer destinations.

## Content rules

State the appointment context and next action without exposing payment identifiers, access tokens, document contents, provider credentials, or sensitive operational details. Explain provider-hosted handoff accurately.

## Failure handling

Use honest, generic customer-safe messages and a staffed support path. Do not disclose internal delivery or system errors.
