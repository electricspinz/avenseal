# Incident Response

## Purpose

Provide a safe, high-level response model for customer-impacting or security incidents.

**Status:** Planned / working standard
**Last Updated:** 2026-08-08

## First response

1. Protect customers and stop unsafe activity using approved controls.
2. Preserve only necessary evidence; do not copy secrets, tokens, document contents, or customer data into informal channels.
3. Notify the designated operational and technical owners.
4. Assess scope, customer impact, and whether an external provider must be contacted.
5. Communicate only approved, factual updates.

## Scope boundaries

This document does not establish legal notification obligations, retention periods, or security certifications. Those require approved legal and operational policy.
